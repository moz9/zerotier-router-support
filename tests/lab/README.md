# Лаборатория: настоящие программы роутеров на ПК

Здесь то, что нельзя проверить заглушками: поведение самих программ ZeroTier и сторожа рядом с ними. Всё работает на ПК в WSL (Ubuntu 24.04, от root), роутеры не затрагиваются и не опрашиваются.

## Что это такое

- **Корни** (`lab-roots.sh`): две копии корневой файловой системы роутера, OpenWrt 24.10 с ZeroTier 1.14 и OpenWrt 25.12 с ZeroTier 1.16; откуда взять программы, задаётся переменными (см. заголовок `lab-roots.sh`). Здесь проверялись 24.10.5 с 1.14.1 и 25.12.6 с 1.16.2. Программы — те самые файлы aarch64, что стоят на роутерах; запускаются через qemu. Ключи, Network ID, настройки и личные данные источников из корней удаляются.
- **Сеть** (`lab.sh`): четыре узла, каждый в своём сетевом пространстве и своём пространстве процессов, на одном закрытом мосту без выхода наружу. Серверы ZeroTier из лаборатории недоступны; их роль играет свой узел.

| Узел | Роль |
|---|---|
| M | свой корневой сервер (вместо серверов ZeroTier) |
| C | контроллер сети (вместо my.zerotier.com), своя закрытая сеть |
| B | обычный участник — «компьютер администратора» |
| A | испытуемый роутер: программа нужной версии |

Контроллер, корень и B всегда работают на 1.14.1: в пакете 1.16.2 контроллера нет.

## Опыты

| Сценарий | Вопрос | Время |
|---|---|---|
| `guard-ash.sh` | набор `tests/guard-scenarios.sh` оболочкой ПК и оболочками роутеров (BusyBox 1.36.1 и 1.37.0), затем shellcheck | ~25 мин |
| `e1-run.sh <24.10\|25.12>` | что ZeroTier хранит; что происходит после перезапуска без контроллера с сохранёнными настройками и без них; повреждённые настройки; отказ контроллера | ~25 мин |
| `e1b-both.sh` | сохранённые настройки старше срока пропуска (30 минут): адрес есть, а доступ? | ~40 мин |
| `e2-run.sh <24.10\|25.12>` | настоящий сторож рядом с настоящей программой ZeroTier и **штатным** `/etc/init.d/zerotier` | ~20 мин |
| `e3-run.sh` | через сколько сам ZeroTier замечает полный обрыв связи | ~12 мин |
| `e4-run.sh <24.10\|25.12>` | обновление уже установленной (опубликованной) версии до новой тем же сценарием, что запускает инструмент управления; повреждённая загрузка, обрыв посередине, потеря связи | ~5 мин |
| `e5-run.sh [24.10] [ревизия]` | роутер, где ZeroTier запускает сценарий производителя (как у RouteRich: папка на флеше, `list join`, без перезапуска программы системой): что делает опубликованная версия, обрыв новой посередине, установка новой до конца, сторож без перезапуска системой, подстановка сохранённых настроек | ~7 мин |
| `all-after-change.sh [skip-e5]` | всё, что нужно после изменения помощника, установщиков или сторожа: `e4` на обеих версиях, `e2` на 25.12, `e5`, затем `guard-ash.sh` — по очереди | ~1,5 ч |

Запуск только файлом сценария:

```powershell
# из корня репозитория; откуда брать программы роутеров для lab-roots.sh — в его заголовке (переменные ZT_LAB_*)
wsl -d Ubuntu-24.04 -u root -- bash tests/lab/lab-roots.sh
wsl -d Ubuntu-24.04 -u root -- bash tests/lab/e2-run.sh 25.12
```

Протоколы — в `/var/tmp/zt-guard-lab/results/`. Итоги прогона 14.11.2026 — в [RESULTS.md](RESULTS.md).

**Нельзя править сценарий, пока он выполняется**: bash читает файл по ходу работы, и правка на лету меняет то, что выполнится дальше. `lab.sh` к тому же перечитывается при каждом запуске программы узла.

## Что в `e2` настоящее, а что заменено

Настоящее: программа ZeroTier, сеть ZeroTier между узлами, `/etc/init.d/zerotier` из пакета, `/etc/rc.common`, оболочка, `uci`, `jsonfilter`, `pidof`, `pgrep`, сам сторож в режиме службы.

Заменено (`stand-ins/`):

- `mini-procd` и `ubus` — вместо procd. Правила перезапуска взяты из исходников procd: через 5 секунд после выхода, не больше 5 быстрых падений подряд, затем отказ до нового запуска службы её сценарием. Сценарий запуска при таком перезапуске не выполняется. Если сценарий не просил перезапуска (`procd_set_param respawn`), вышедшая программа не поднимается, пока сценарий снова не запустит службу.
- `initd-zerotier-vendor` (только в `e5`) — сценарий запуска ZeroTier, написанный для лаборатории по поведению сценария RouteRich (не его копия): папка ZeroTier на флеше, сети из `list join`, без перезапуска программы системой, `stop` удаляет настройки сетей и перезагружает файрвол.
- `reboot` — только записывает, что перезагрузку попросили.
- `nft` и `/etc/init.d/firewall` — qemu не пропускает netlink файрвола; отвечают как роутер с исправным файрволом.
- Подкопа нет вовсе.

Время в `e2` сжато через собственный файл настроек сторожа: лестница, которая на роутере занимает полчаса, проходит за полторы минуты.

Поэтому на ПК не показано: настоящий procd, настоящая перезагрузка файрвола и роутера, пауза Подкопа, память и нагрузка на железе.
