## Серьёзные

### 1. Установка с Mac по паролю не работает

`install.sh`, функция `run_expect_scp_password`: `spawn scp ... $env(PAYLOAD_DIR)/* ...`.
`expect` запускает команду без shell, `*` не раскрывается, и `scp` получает буквальный путь `.../zrs-files/*` — файл не найден. Код возврата не проверяется (`eof {}`), поэтому дальше запускается несуществующий `/tmp/zrs-files/router-install.sh`. Рабочий только вариант с уже установленным ключом.

Предложение: через `expect` по паролю только добавлять публичный ключ в `/etc/dropbear/authorized_keys` (передавать ключ через stdin ssh), а копирование и установку всегда выполнять функциями `run_scp_key` / `run_ssh_key`.

### 2. Ошибки установки скрываются, в конце всегда «Готово.»

`install.sh`: удалённая команда `sh /tmp/zrs-files/router-install.sh /tmp/zrs-files; echo __ZRS_DONE__`. Из-за `;` ssh возвращает код `echo` (0), и при падении `router-install.sh` скрипт всё равно печатает «Готово.». В expect-ветке код дочернего процесса тоже не проверяется.

Предложение: убрать маркер или использовать `&&`, передавать реальный код возврата; в expect проверять `lassign [wait] ...` и выходить с ненулевым кодом.

### 3. Долгие операции из LuCI блокируют rpcd

`openwrt/usr/share/rpcd/ucode/zerotier.support`, функция `run`: синхронный `popen` внутри процесса rpcd.
`install` (`opkg update`/`install`, перезапуск, до двух ожиданий по 45 с в `wait_for_zerotier_ready`), `configure` и `restart` выполняются десятки секунд. Всё это время RPC LuCI недоступен, а браузер, скорее всего, получит таймаут и покажет «Команда не выполнена», хотя операция продолжается.

Предложение: запускать изменяющие действия в фоне (lock-файл, вывод в `/tmp/zerotier-support.log`, PID), сразу возвращать ответ, а в панели опрашивать статус или лог до завершения. Это изменение крупнее остальных — лучше отдельным PR.

### 4. Одним кликом можно отрезать себе удалённый доступ

`openwrt/www/luci-static/resources/view/services/zerotier.js`: кнопки «Отключить от сети» и «Выключить ZeroTier» срабатывают без подтверждения. Если администратор зашёл через ZeroTier, доступ пропадёт сразу.
Кроме того, «Отключить от сети» берёт ID из поля ввода, а не из сохранённой конфигурации, а `leave_network` в helper удаляет секцию `zerotier.router_support` независимо от того, совпадает ли ID.

Предложение: окно подтверждения `ui.showModal` с предупреждением о потере доступа через ZeroTier; для leave использовать сохранённый ID (или удалять секцию только при совпадении ID).

## Средние

### 5. `set -e` не действует внутри функций, вызванных через `if !`

`helper`, `install_or_upgrade`: `if ! ensure_transport_independence || ! ensure_firewall`. По POSIX внутри таких вызовов `set -e` отключён, поэтому молча игнорируются сбои `uci set` (в `ensure_firewall`), `uci commit zerotier`, `mv`, `cp` и других команд без явного `|| return 1`, и откат не срабатывает.

Предложение: добавить `|| return 1` ко всем значимым командам в этих функциях (как уже сделано в `ensure_ping_rule`).

### 6. Секрет ZeroTier скрывается только в секции `global`

`helper`, `print_technical_details`: `sed "s/^zerotier\.global\.secret=.*/..."`. В старых конфигурациях OpenWrt основная секция называлась `sample_config` (или была анонимной), и init-скрипт сохранял сгенерированный secret в uci — тогда он попадёт в диагностику в LuCI.

Предложение: `sed "s/^\(zerotier\.[^.=]*\.secret\)=.*/\1='<hidden>'/"`.

### 7. Резервные копии засоряют `/tmp` и доступны не только root

`router-install.sh`, блок `== Backup ==`: каждый запуск оставляет в RAM и распакованный каталог `/tmp/zt-support-backup-<ts>/`, и `.tar.gz` с тем же содержимым. Внутри полный `sysupgrade -b` (`/etc/shadow`, ключи Wi-Fi, identity ZeroTier), каталог создаётся с правами по umask 022.

Предложение: `umask 077` на время бэкапа, `rm -rf "$backup_dir"` после упаковки, хранить только последние 2–3 архива.

### 8. `jq` нигде не устанавливается

`helper`, `ensure_transport_independence`: без `jq` установка падает, если у ZeroTier уже задан собственный `local_conf_path`; исключение интерфейса WARP без `jq` тихо пропускается.

Предложение: ставить `jq` вместе с `zerotier` в `pm_install_zerotier` (и в `router-install.sh`), если его нет.

### 9. Лишние права в ACL

`openwrt/usr/share/rpcd/acl.d/zerotier-support.json`: панель работает только через ubus-объект `zerotier.support`, но группа даёт прямую запись в uci `firewall` и `zerotier` и чтение `dropbear` и `podkop`.

Предложение: убрать секции `uci` из read и write (перед этим проверить, что панель работает).

### 10. Настройки, вероятно, не переживут обновление прошивки

После sysupgrade в uci останется `zerotier.global.local_conf_path=/etc/zerotier-router-support.conf`, но сам файл, helper, файлы LuCI и rpcd по умолчанию не сохраняются. Сохраняется ли `/etc/nftables.d/`, не проверялось. Если пакеты переустановит ASU/owut, ZeroTier запустится со случайными портами без обхода Podkop — именно тот сценарий, от которого защищает проект.

Предложение: добавить `/lib/upgrade/keep.d/zerotier-router-support` со списком файлов проекта, либо хотя бы явно написать в README, что после обновления прошивки установку нужно повторить. Поведение проверить на реальном роутере.

### 11. `configure` без отката

`helper`, `configure_network`: в отличие от `install`, нет снимка, проверки и отката. При сбое в `ensure_transport_independence` правки uci остаются несохранёнными в staging (`/tmp/.uci`), и их применит следующий посторонний `uci commit zerotier`.

Предложение: использовать тот же механизм snapshot/restore, что и в `install_or_upgrade`, либо делать `uci revert zerotier` при ошибке.

## Мелочи

- `helper`, `ensure_transport_independence`: на путях ошибок остаются временные файлы (`$merged_conf` после неудачного `jq -e`, `$nft_previous`, если нет `fw4`).
- `install.sh`: при Ctrl-C во время ввода пароля терминал остаётся без эха — нужен `trap 'stty echo' INT TERM EXIT` вокруг `stty -echo`.
- `router-install.sh`: перезапуск dropbear не нужен (`authorized_keys` читается при каждом подключении) и лишний раз рискует SSH-сессией.
- `install.sh`: в комментарии ключа осталась метка `codex-router-support`; `router-install.sh` ищет ключи по ней, поэтому при переименовании учесть старые ключи.
- `router-direct-install.sh` качает файлы по одному с `main` без фиксации версии: коммит во время загрузки даст смесь версий. SECURITY.md рекомендует теги — стоит отразить это и в README (например, `ZRS_BASE_URL` на тег или коммит).
- `router-direct-install.sh`: `trap cleanup EXIT INT TERM` при INT/TERM не завершает скрипт — добавить `exit` в обработчик сигналов.
- Нет CI. Предложение: GitHub Actions с shellcheck, `node --test tests/*.mjs` и `sh tests/local-conf.sh ...`. Большинство тестов проверяют исходник регулярками — по возможности заменить на поведенческие тесты с заглушками `uci`/`nft`/`zerotier-cli`, как в `tests/ping-rule.test.mjs`.
